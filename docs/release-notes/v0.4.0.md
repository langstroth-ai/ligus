Ligus (short for *ligustica*) 0.4.0 lets you approve a box or a computer by comparing a short code, gives you one profile and named devices, brings stricter device rules, decision cards from agents (Claude Code's own prompts included), proposal archiving, scratch repositories, and keeps secrets out of the database. Upgrade every device, boxes and phones included.

## What's new in 0.4.0

- **Approve by comparing a code.** An Admin copies the workspace's approval address (`ligus admit address`, or the workspace menu → **Admit a box…**). A box runs `ligus admit request --to ligusaddr1:…`, a computer `ligus devices request --to ligusaddr1:…`. The request reaches your Inbox through the relay, both screens show the same 8-symbol code, such as K7Q4 M9X2, and **Codes match** takes one passkey. If the codes differ, choose **Don't match** and nothing is granted. On the phone, an approval opened from a notification shows three codes and asks which one the box shows. `ligus approvals list` and `ligus approvals approve` approve from a terminal, and `ligus admit address --reset` cuts off an address that leaked. Pasting the request and comparing the fingerprint still work as before.
- **One profile.** Your name and picture are one profile across every workspace you're in, and a change shows everywhere, in past messages too. Pictures are PNG, JPEG or WebP up to 16 KB. Change them in **Settings → Profile**, or with `ligus profile set`. A name that looks like another account's, an agent's or Ligus shows with a short tag, as in Ana#3f2c.
- **Named devices.** **Rename…** in My devices, `ligus devices rename` or `lt --plain device-rename` names a device for everyone. A box names itself from `--label`, and a linked computer after its link request. A computer that was approved but never redeemed says so and offers **Remove**.
- **Linking a computer finishes on the computer.** When it redeems the code, the computer accepts your desktop's approval. If it was already a separate member of the workspace, it retires that member into you, and the old member's history stays as it was. It does this only when it's safe; otherwise it says so and an Admin removes the member in People.
- **Stricter device rules (rules 3).** A device's approval counts only once the device itself accepted it, so a certificate someone else puts on your device key does nothing. Duplicate members retire into their person, and model keys are refused on the log. A new workspace moves to rules 3 with its founder's first passkey. For an existing workspace, an Owner opens **Settings → Security → Stricter device rules**, checks the list of devices whose approval would stop counting, and switches with a passkey; there is no way back. Devices still on Ligus 0.3 can read a rules 3 workspace but not write to it.
- **Decision cards from agents.** Agents ask with `ligus_ask_person` (the person who asked for the turn) or `ligus_ask_room` (anyone at or above a role, or a number of people who must agree). A card has 2 to 5 options or Yes and No, and can take a reply. Cards show in the chat on the desktop, in lt and on the phone, and only the people a card names can answer it. On the phone every answer asks for Face ID. Each card says what your answer does, and the agent's words are plain text, with no formatting or links. **Not now** on a room card is only your own abstention. An agent's permission request is a grant card that shows the exact command or file change, with **Allow once** and **Deny**.
- **Claude Code's permission prompts, in Ligus.** `ligus hook install` adds Ligus as the `PermissionRequest` hook of a Claude Code session you run yourself. Its prompts then show as grant cards on the desktop and your phone while the terminal waits. **Allow once** always asks for your passkey, or Face ID on the phone. With no answer, Claude Code shows its own dialog. The desktop app answers these prompts; a `ligus serve` box and lt don't. Send them to a workspace of your own: every member can read every chat. `ligus asks list`, `answer` and `decline` answer questions from a terminal.
- **Archiving proposals.** A settled proposal's menu has **Archive**, which takes it out of the Review pane for everyone. Every proposal has **Hide for me**, which hides it on this device only. A settled proposal also archives itself after 7 days; an Admin changes that, or turns it off, in **Settings → Review**. **Archived proposals**, in the Review pane's **⋯** or ⌘K, lists them with search and **Restore**. A proposal that still waits on someone is never archived.
- **Scratch repositories.** **New scratch repo**, the first choice in every repository picker, starts an empty repository for a chat on the host that runs its agents. Agents work in it as in any repository, with the same branch, proposals, approvals and sandbox. **Keep it as a repo** moves it out of the scratch folder, with an optional **Publish to GitHub (private)** that runs only after you confirm the account and name. A scratch repository nobody kept is removed after 14 days without activity, with a notice in its chats two days before, and the chats keep their history. One you create from the phone lives on your box and isn't added to the workspace's repositories. On the command line: `ligus repo scratch` and `ligus repo keep`.
- **Attachments stay on the relay while they're used.** The device that shared a file, its person's other devices and every Admin's desktop renew it on the relay in the background, about every ten days. The relay's maximum age still applies (a year by default). When the relay no longer has a file, its card says **This file expired on the relay**.
- **Secrets out of the database.** Invite and admission seeds now live only in the OS secret store. Seeds an older version wrote to the database are copied there, then removed from the database once the invite or admission is closed. Sync progress is kept per relay and per workspace. The database records its layout version: a version of Ligus that finds a database written by a newer one opens it read-only, and the CLI exits with code 3. `ligus doctor` reports the version and lists database backups.

## Changes you might notice

- An open proposal that an earlier version dismissed shows in Review again, since nothing that still waits on someone is archived. Reject it, or hide it for yourself.
- Questions from agents are plain text everywhere, older ones included.
- The relay's own member roster is deprecated for Ligus workspaces; every device enforces the workspace's signed roster.

## Upgrading

- **Upgrade every device.** That means desktops, `ligus` CLIs and lt, `ligus serve` and worker boxes, and phones. A device on 0.3 is read-only on a rules 3 workspace, and its answers to the new cards are kept but not counted. On a workspace still on rules 2, 0.3 and 0.4 devices sync normally.
- **Upgrade the relay, if you run your own.** Approving by code and renewing attachments need a langstroth-relay release newer than 0.3.2. On an older relay, the desktop keeps the paste and fingerprint path, and `ligus admit request --to` and `ligus devices request --to` stop with exit code 3 and name the paste command to run instead. Attachments then expire at the relay's retention, as before.
- **Going back to 0.3** still opens your data, but invites issued by 0.4 must be issued again there.

## Install or update

The desktop app updates itself. To install:

```sh
brew install --cask langstroth-ai/ligus/ligus-app   # desktop app (macOS)
brew install langstroth-ai/ligus/ligus             # CLI
```

Or download an installer below. CLI binaries come with `.sha256` checksums. With Homebrew, `brew upgrade ligus` updates the CLI.
