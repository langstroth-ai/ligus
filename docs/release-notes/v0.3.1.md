Ligus (short for *ligustica*) 0.3.1 is a security release. It covers agents' permission requests, devices that act only for their own account, and model API keys that are never stored in the workspace. It also makes linking a computer easier and the relay claim calmer. Upgrade every member of a workspace.

## Security

- **"Allow" always means once.** If an ACP agent offered only a permission that lasts the rest of its session, Ligus used to pick it, so one approval, or a call your tier allows, granted a standing permission nobody chose. Now Ligus picks only the one-time option. When an agent offers nothing else, Ligus asks a person and says that the permission lasts the session, and it grants it only on their explicit yes. With no one to ask, it refuses.
- **Only the host can ask for permission.** Before, any member or box could post a question that looked like a host's permission request. Now a permission request counts only when it comes from the device that runs the agent's turn. Anything else shows as a plain question, attributed to whoever posted it, and grants nothing. The host waits only on the request it posted itself.
- **Only the asker closes a question, and only the right people grant.** An agent's question can be closed only by the agent or its host. An answer to a permission request counts only when it comes from the host's own person or the agent's owner, sent from one of their own devices. Other closes and answers stay in the chat and change nothing.
- **Devices act only for the account they chose.** A device key is public, so any member could certify someone else's device for their own account. That could stop a `ligus serve` box, break a phone, block linking a computer, let someone act as a host's owner on that owner's private agents, inherit a removed member's history and agents, or keep a removed member's device receiving new workspace keys. Now a device acts only for accounts that certified it and that it has signed as itself. A certificate like that blocks and redirects nothing. It is shown quietly, in `ligus devices list`, `/v1/health` and Add a computer.
- **Model API keys are never stored in the workspace.** `ligus add-runtime --secret` is gone; it is now a usage error. Give a workspace runtime a key with `--secret-ref <NAME>` and set `LIGUS_WS_SECRET_<NAME>` on each worker. A key an older version stored in the workspace is never used, shown or exported. Such a runtime reads as "stored key (unused)" and runs only if it can run without a key, and `ligus doctor` warns about it (`runtimes.inline-key`).

## What's new in 0.3.1

- **Link a computer without retyping codes.** On the desktop, Add a computer's last step is **Copy for lt**, which copies the grant alone, and this desktop's fingerprint has its own copy button. On the computer, run `ligus devices redeem` (or `lt --plain link-redeem`) with nothing after it. It reads a hidden paste or the clipboard and asks *Is that your desktop? [y/N]*. `ligus devices request` prints only the request on stdout, and has `--copy`. A link that is waiting shows in `ligus status`.
- **Linking is easier to find.** In ⌘K, use **Add a computer to my devices…** or **My devices**. In People, a member that looks like you on another computer says so and offers to link it.
- **Revoked devices are out of the way.** My devices folds them into a collapsed **Revoked (N)** group. A device whose cleanup isn't finished stays in view, with **Retry now**.
- **A calmer relay claim.** People offers **Claim ownership** only when this device's relay token names an account. On a self-hosted relay without such a token, it offers **Add a relay token**. On the community relay, or a relay with membership off, it offers nothing. The warning is one line, "Relay doesn't check membership", with the details behind **?**. A refused claim says what's missing and how to fix it.
- **Refusals say why.** A device signing as someone who is no longer a member, such as an lt left open while the computer was linked, is told to link the computer again or ask for an invite. A role that is too low is told which role it needs.

## Upgrading

- **Upgrade every member.** The permission-request rules apply on each member's own device. A device still on 0.3.0 still shows a forged permission request as a real one, and treats someone else's close as closing the question. The host already checks who granted a permission, so a 0.3.0 device can't grant one by mistake. Upgrade every desktop, `ligus` CLI and `ligus serve` box. 0.3.0 and 0.3.1 devices sync normally.
- **Rotate a model key stored in the workspace.** If `ligus runtimes` shows "stored key (unused)", every member's device received that key. Rotate it with the provider, then set it on each worker with `--secret-ref`.
- **`ligus add-runtime --secret` is removed.** Update scripts to use `--secret-ref`.

Full list: [What's new](https://docs.langstroth.ai/ligus/reference/whats-new/).

## Install or update

The desktop app updates itself. To install:

```sh
brew install --cask langstroth-ai/ligus/ligus-app   # desktop app (macOS)
brew install langstroth-ai/ligus/ligus             # CLI
```

Or download an installer below. CLI binaries come with `.sha256` checksums. With Homebrew, `brew upgrade ligus` updates the CLI.
