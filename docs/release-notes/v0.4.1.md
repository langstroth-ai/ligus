Ligus (short for *ligustica*) 0.4.1 fixes what new users ran into while setting up agents. Replies read in order, an agent's question reaches the phone of the person it asks, a chat that refused every message sends again, Add an agent picks its host in one step, and a phone sees only its own person's direct messages. Update your desktops and boxes.

## Fixes in 0.4.1

- **Replies read in order.** An agent's reply is stamped with when it was posted, not when its turn started, on the desktop and the phone. A question you already answered sits above the reply that reports your answer. Replies from devices still on 0.4.0 show right too, once the device or box showing them is updated.
- **An agent's question reaches the phone of the person it asks.** When a box had joined the workspace as its own member, a question an agent asked a named person never pushed to that person's phone. A box now works out questions, mentions and replies to you for each paired phone's person, and sends each only to that person's phones.
- **A chat stuck on "this draft is out of date" sends again.** After older reply pieces were pulled back from the relay, every message from this computer to that chat was refused, and Retry didn't help. A message now links to this computer's newest event in the chat, whatever order the relay delivered them in. A chat already stuck recovers once you update.
- **Add an agent picks where it runs in the same step.** "Runs on" lists this device, your always-on boxes and your other computers, and saving writes the agent and its host together, with one passkey confirmation. An agent on a model gateway starts on the box that offers that gateway, and says so if you pick a host that doesn't.
- **A model gateway runtime is OpenAI-compatible.** Picking a model gateway in Add a runtime switches the kind to OpenAI-compatible and hides the Ollama-only settings. Type the model the gateway serves. Choosing Ollama during first setup offers the models installed on this computer instead of `gpt-4o`.
- **Setup says what's happening.** An agent whose host is offline says so in the chat, once while it stays offline. Devices are never named by a hex id: an unnamed one shows what it is and when it was added, such as "Phone · added 24 Nov". Errors are never lost behind other notices; many fold into one "N problems" notice. The relay roster line in People can be dismissed. Push that was never turned on reads grey "Not set up" rather than red.
- **A step that needs your passkey says where to confirm it.** In a workspace with stricter device rules, `ligus setup` used to stop with "refused" (exit 6) and point at `ligus doctor`. It now stops as a person's step (exit 4) and says to confirm in the desktop app, or to run it again with the new `--recovery-words-file PATH`.
- **The chat says when an agent runs on a host's default runtime.** A worker or box without an agent's runtime runs it on its catch-all entry in `runtimes.toml`, with that entry's model. The chat now says so once, and says why when there is no catch-all and the turn is refused.
- **Scratch repositories survive a damaged list.** If a box can't read its list of scratch repositories, it keeps the file aside instead of replacing it with an empty one.
- **A box follows your notification switches.** A box sends only the kinds of notification the phone's switches allow, and Forget host on the phone tells the box to stop pushing to it first.

## Security

- **A phone sees only its own person's direct messages.** A box used to list every DM it holds to every paired phone, and streamed their messages and typing to every phone. Now a phone sees, in its chat lists and its live updates, only the DMs its person is in, and none when the box can't tell whose phone it is.
- **Proposal notes from a phone are refused for now.** A note sent from the phone was written as the box, not as you. The box now refuses it with "Add notes from your desktop for now." Votes and *Send to agent to revise* still work from the phone.

## New in 0.4.1

- **Agents that run their own helper server (Linux).** The Google Antigravity CLI (`agy`) starts a local language server, which the agent sandbox refused. A per-agent **May run local servers** switch, off by default and the workspace Owner's, allows it: **Settings → Sandbox**, `ligus agents set <agent> --local-servers on`, or `ligus setup agent --harness antigravity --local-servers`. With bubblewrap each turn has its own loopback, which can't reach services on the host. It isn't available on macOS yet, because the Mac's sandbox can't keep a listener to loopback only, and agy's error now says which applies.

## With this release

- **Phone app.** A problem you dismissed stays dismissed until something changes, and connection problems clear once the phone reconnects. A settled question sits in the chat at the time it was answered, and a finished reply moves to its time. Pairing says `ligus pair`, and push that was never set up reads grey. Forget host turns that box's notifications off first, and the note field on proposals is hidden on a real box for now.
- **lt.** This computer's name is chosen once and stays the same when the network name changes. Setup checks Antigravity's sign-in instead of warning that it can't tell. Linking this computer never fails silently: it waits for the desktop's approval to arrive, says when a step isn't confirmed here yet and offers a retry, and says when the relay can't be reached.
- **Docs.** The box pages say how a box really joins (as its own member, approved by comparing a code), and cover model gateways and upgrading a box.

## Upgrading

- **Update desktops and `ligus serve` and worker boxes.** The phone fixes (your own DMs, notes, notification switches, questions pushed to you) happen on the box, so update the box your phone pairs with. 0.4.0 and 0.4.1 devices sync normally.
- **May run local servers** is ignored by 0.4.0 devices, which keep refusing a listener. Update the host that runs the agent.

Full list: [What's new](https://docs.langstroth.ai/ligus/reference/whats-new/).

## Install or update

The desktop app updates itself. To install:

```sh
brew install --cask langstroth-ai/ligus/ligus-app   # desktop app (macOS)
brew install langstroth-ai/ligus/ligus             # CLI
```

Or download an installer below. CLI binaries come with `.sha256` checksums. With Homebrew, `brew upgrade ligus` updates the CLI.
