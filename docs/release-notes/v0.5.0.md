Ligus (short for *ligustica*) 0.5.0 makes you one person on all your devices: link a new device with a short code, and one link brings all your workspaces. Adding an agent is one step, with its model and where it runs. A turn that can't run says so instead of quietly falling back, and a Set up Ligus checklist shows what's left. Update the box and every device first.

## What's new in 0.5.0

- **One person, one member.** The first run now asks **Is this your first device with Ligus?** Choose **I already use Ligus on another device** and this device becomes one more of your devices, never a second you. It asks no name and makes or joins nothing. lt asks the same question.
- **Link a device by typing a short code.** **Settings → Profile → My devices → Add a computer** shows a 6-character code such as `K7Q-4MX`. Type it on the new device (in its first run, in lt's **Add to my devices**, or with `ligus devices request --code K7Q-4MX`), then compare the code both screens show and confirm with your passkey. A code works once, for 10 minutes, and the relay sees neither the code nor the address. `ligus devices link` shows a code from a terminal.
- **One link brings all your workspaces.** Linking a new desktop or lt adds it to every workspace your other desktop can add it to, not only one. Your desktop asks your passkey once per workspace ("in “Beta” (2 of 3)"), and the new computer lists how each one went, with **Try again** where it can help.
- **Confirm a passkey step on your desktop or phone.** A terminal step that needs your passkey, such as `ligus setup`, `ligus admit issue`, `ligus devices approve` or `ligus phones certify`, no longer stops with "do it in the desktop app". It sends the exact change to your own desktop, or to your phone through its box, with a code, and waits. **Confirm with passkey** (or **Confirm with Face ID**) writes it; **Not me** writes nothing and offers to revoke the device that asked. Only your own devices can ask or answer. `--recovery-words-file` still works instead.
- **Add an agent in one step.** One form, the same in the desktop, in lt and in `ligus setup agent`: a name, what answers (a coding CLI, a model gateway or hosted API one of your hosts offers, a model server, or an API key kept on this device), its model, and **Runs on**, then one button. There is no runtime to add first and no separate host step. On the command line, `--source`, `--model` and `--runs-on` replace `--harness` and `--gateway`, which still work.
- **Change model… and Runs on… for each agent.** An agent's **⋯** menu (Tools pane, and in lt) opens the same form with just that field: the models its source offers where it runs, or your devices and the hosts that offer its source, each with its state. On rules 4, changing your own agent's model within the same source needs no passkey. On the command line: `ligus agents set <agent> --model M` or `--runs-on here|HOST`.
- **A turn that can't run says so.** A message to an agent whose host is offline gets one quiet line under it, such as "@coder runs on build-1, which is offline. It will answer when build-1 is back." It also says when the host was removed or can't run the agent as asked. **Run here this time** runs that one turn on your device, when the agent is yours and this device can run it, and the host doesn't answer it again when it's back. A reply that was stopped reads **Canceled**, one that failed **Failed**, with the model and host that ran it.
- **Set up Ligus: one checklist.** **Settings → Set up Ligus** on the desktop, `ligus setup` in a terminal, lt's setup screen and the phone's Health show the same rows: you, your passkey and recovery key, this device's name, your other devices, your phone and push, an always-on box and its updates, your agents and where each answers, and the workspace and its rules. Each row has one next step, and what you never set up reads grey **Not set up**, never red. **Clean up** lists the leftovers (members who left, revoked or idle devices, former members' hosts, old agent names) with one action each, and removes nothing until you confirm.
- **Your phone in one flow.** Scan the desktop's code, check the name the phone suggests ("Ana's iPhone"), and choose **Add**. That one confirmation also says the phone is yours, so the separate "Confirm this phone is Ana's" question no longer follows. The phone then asks once about notifications. You can rename the phone from the phone (**Settings → This phone → Rename**) in a rules 4 workspace.
- **Leave a workspace.** Right-click a workspace and choose **Leave workspace**: the others see you as **asked to leave** until an Admin removes you, and this device stops syncing it. Leaving isn't revoking: your other devices keep their keys. A box leaves with `ligus serve leave --yes`, and lt from its palette.
- **Device states.** My devices shows a device that was approved but never used as **pending**, and one with nothing for 30 days as **idle**, both grey with **Remove**. Workers & hosts shows an idle host the same way. Forget host on the phone now tells the box, and your desktop asks whether to remove the phone too.
- **The box acts for each phone's person.** When several people's phones use the same box, unread counts, "you" in People, which agents you may use and which notifications are yours are worked out for the person each phone belongs to, not for the box. Read positions are kept per person, so your phones share them.
- **Gateways and secrets on a box, in one command.** `ligus gateway add NAME --url URL --api openai` lists a model gateway or local model server on a box (`list`, `check` and `remove` do the rest). It stores a key only as the path of a file on the box, and says plainly that a box with a gateway sends model traffic only through its gateways (`--not-exclusive` changes that). `ligus secrets set NAME -` keeps a workspace secret in the device's secret store and declares it for the workspace, with no environment variable; `ligus secrets list` and `ligus secrets rm` do the rest. No command prints a secret.
- **Admit a box by matching a code.** `ligus setup box --to ligusaddr1:…`, or `deploy/local/ligus-local configure --admit-to ligusaddr1:…`, sends the box's join request to the workspace: the box prints a code, the Admin's desktop or phone shows the same one, and one passkey admits it. Nothing is pasted.
- **Box update notices.** A box or worker on an older release shows one grey line in **People → Workers & hosts**, such as "0.4.1 → 0.5.0 available · how", and the phone's Health shows the same. **how** says to run `ligus-local upgrade` on the box, which upgrades and restarts it in one step. Ligus never upgrades a box on its own. `brew services start ligus` now also runs a box.
- **Workspace rules 4.** New workspaces start on rules 4, where every device checks what an agent runs and where it runs: an agent can only be placed on a host that exists, is trusted and offers what the agent runs; a Contributor places their own agent on their own computer, and only an Admin places one elsewhere. **Run here this time** counts on every device. An existing workspace keeps its rules until an Owner upgrades it in **Settings → Workspace rules** (or `ligus workspace rules upgrade`), which first lists each device that will go read-only and its build, then takes one passkey. There's no going back. Devices on 0.4 or older can still open a rules 4 workspace, but only to read it: they can't send messages or change anything there until they update.

## Changes you might notice

- **No silent fallbacks.** An agent whose runtime your device doesn't have, or has without its key, used to answer on Claude Code without saying. Its turn now says "can't run here" and why, and **Use Claude Code instead** (in the line's **⋯** menu) runs that one turn on Claude Code. A device no longer answers for an agent whose host didn't pick the turn up; the turn waits where it belongs. A box or worker refuses what it can't run and says why, instead of answering with an error.
- **A computer runs only its own person's agents.** An agent someone else placed on your computer no longer runs there unless you turn on **Settings → Models → Run other people's agents on this computer**. Workers and boxes still run any agent placed on them.
- **A box or worker uses only the secrets it declared** in its `host.toml`. On first start a box declares the secrets it already has, so existing setups keep working; a new one needs one line, and the error says which.
- **Agent templates are gone.** The Add an agent form replaces them. Settings no longer lists saved templates, and a portable config no longer carries agents (the import summary says it skipped them). Templates you saved stay in `settings.json`, unused.
- **Storage upgrade.** The first start of 0.5 upgrades this device's database, after making a backup, and moves the scratch repository list and folder bindings into it. A 0.4 build then opens that data read-only. `ligus doctor` lists the backups.
- **Linking works when you have a profile picture.** The code your desktop sends a new device no longer carries your picture, which made it too large to send through the relay or paste. The new device shows your picture once it has synced.
- **A box keeps the name you gave it** instead of resetting it from `--label` each time it starts.
- **A host counts only when its own computer registered it**, so nobody can register a host under someone else's computer.

## Upgrading

- **Update the box and every device before you upgrade a workspace's rules.** That means desktops, `ligus` CLIs and lt, `ligus serve` and worker boxes, and phones. Settings → Workspace rules lists any device still on an older build. Once a workspace is on rules 4, a device on 0.4 or older can only read it until it updates. Workspaces you don't upgrade keep working with 0.4 devices.
- **The relay needs 0.5 for short codes.** Linking by short code needs langstroth-relay 0.5.0 or newer. With an older relay, Add a computer shows the approval address to copy, as before, and everything else works.
- **Going back to 0.4** opens this device's data read-only, because of the storage upgrade.

Full list: [What's new](https://docs.langstroth.ai/ligus/reference/whats-new/).

## Install or update

The desktop app updates itself. To install:

```sh
brew install --cask langstroth-ai/ligus/ligus-app   # desktop app (macOS)
brew install langstroth-ai/ligus/ligus             # CLI
```

Or download an installer below. CLI binaries come with `.sha256` checksums. With Homebrew, `brew upgrade ligus` updates the CLI.
