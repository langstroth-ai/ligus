Ligus (short for *ligustica*) 0.3.0 brings a calmer desktop, guided setup for everything you connect, a way to add a second computer to your own devices, custom themes, and security fixes for agent tools.

## What's new in 0.3.0

- **A calmer desktop.** Lists are one line per row: who or what, then one muted status. A row's actions are in its menu (right-click it, or click **⋯**), each pane shows one main action, and the longer explanations sit behind **?** instead of under every pane. Settings follows the same pattern.
- **Guided setup.** Set up an agent, connect a tool, add a code folder, add a box, add a phone, invite a person or set up a relay, one step at a time. Open a flow from **⌘K → Set up**, type `/setup` in the composer, or run `ligus setup <flow>` (`ligus setup` lists the flows and what this device already has). Each flow checks first, skips what is already done when you run it again, undoes its own changes if a later step fails, and stops at steps only you can do, like a passkey approval. In lt, press `u` or run `lt setup <flow>`. A tool can now be limited to some agents.
- **Add a computer to your devices.** Use Ligus on a second computer (`lt` or the `ligus` CLI) as yourself, not as a second member with your name: on the desktop, **Settings → Profile → My devices → Add a computer**, compare the fingerprint and confirm with your passkey. The CLI has `ligus devices request`, `redeem`, `approve` and `list`; lt has **Add to my devices**. If you already invited yourself, linking offers to remove the duplicate member; its messages keep their name.
- **Themes.** Six palettes, each in light and dark. **Settings → Appearance → Import a theme…** reads your own theme file (TOML or JSON, colours only), and **Export current theme** saves the one in use as a starting point. The same file works in lt.
- **The keychain stops asking (macOS).** After switching between a release and a test or development build, Ligus asks for the keychain once, repairs its items so they trust the release, and doesn't ask again. When macOS refuses access, Ligus says so and what to do; `ligus doctor` reports it as `secrets.keychain-access`.
- **`ligus app` opens the installed app.** It opens `/Applications/Ligus.app` (or `~/Applications`, or the path in `LIGUS_APP`) instead of an old test build or a mounted disk image, and says when the app and the CLI versions differ.
- **@hive still reaches the default agent.** Messages and scripts from the Hive builds that mention `@hive` are answered by the default agent, and its old replies show as Ligus. New agents can't be named `ligus`, `hive`, `primary` or a look-alike of them.

## Security

- **Tool restrictions apply to Claude Code turns.** A tool limited to some agents is left out of the tools Claude Code gets for any other agent.
- **Tokens go only to their own server.** A saved relay access token is sent only to the relay it was saved for, and a tool's token only to its own server. Relay and tool URLs must use https (plain http only for this machine) and can't carry a user name or token; tool errors no longer show the URL.

## Upgrading

- **`ligus setup --apply` is now `ligus setup runtimes --apply`.** The old spelling still works in 0.3.0 and goes away in the next release; update scripts that use it.

Full list: [What's new](https://docs.langstroth.ai/ligus/reference/whats-new/).

## Install or update

The desktop app updates itself. To install:

```sh
brew install --cask langstroth-ai/ligus/ligus-app   # desktop app (macOS)
brew install langstroth-ai/ligus/ligus             # CLI
```

Or download an installer below. CLI binaries come with `.sha256` checksums. With Homebrew, `brew upgrade ligus` updates the CLI.
